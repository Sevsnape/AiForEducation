# AIFOREC 产品说明

> 项目名称：AIFOREC（以学生为中心的学业支持多智能体系统）  
> 行业方向：智慧教育 / AI+教育  
> 文档用途：讲清产品功能、为何需要、对各方用户意味着什么；辅以场景与边界说明  
> 同步范围：与 `docs/` 设计文档、`apps/web` 前端 Mock、`src/aiforec` 后端骨架一致（截至 2026-08-12）

---

## 1. 场景来源

教育场景中，学生学习压力与情绪困扰高度交织：既需要针对知识点的巩固与变式练习，也需要可倾诉、不加压的学业情绪支持。学校侧同时存在教师备课出题、班级学情跟踪、账号与同意策略治理的真实需求。

AIFOREC 选择**混合场景、学生主视角**：有教师协作与管理后台，但产品灵魂是AI支持学生——老师看见「学得怎样」，AI 才真正「懂这个学生」；「懂」的支持侧信息默认只对学生本人开放。

场景动机来自三类一线诉求：

1. **学生**：不会的题需要讲与练，考前焦虑需要被听见；希望与 AI **共创学习计划**、管理自己的历史与成长阶段；不希望情绪内容被老师当作考核材料。  
2. **教师**：组卷与变式成本高，希望按知识点或**上传讲义/试卷文件**出题，并看到授权范围内的薄弱点与提问模块热点，但不应随意介入学生私密情绪档案。  
3. **学校/合规**：未成年人数据与心理健康相关内容需要最小必要、可审计、可拒绝越权访问；同意策略由校方统一配置以及学生一起调整，学情可按班级聚合分析。

---

## 2. 用户痛点

| 角色 | 痛点 |
|------|------|
| 学生 | 辅导与安慰混在一起，容易被继续催刷无意义的题；缺少「只属于我」的连续记忆与可管历史；不敢把真实压力告诉会通报老师的系统；学习计划常靠自己硬撑 |
| 教师 | 出题耗时、难对齐薄弱点与现有材料；若系统把所有心理信息推给老师，既越界又不可用；缺少「班里常问什么模块」的聚合视图 |
| 学校 | 通用聊天机器人难落地：缺三角色权责、缺同意治理、缺审计与危机边界；学情无法按组织/班级合规汇总 |

核心矛盾可概括为：**个性化学习需要数据，心理健康支持需要隐私；二者必须同系统共存，但不能同视图共享。**

---

## 3. 产品怎么用起来（总览）

用户用邮箱密码登录后，按角色进入不同工作台——**同一套智能能力，三套可见范围**：

| 你是谁 | 进入哪里 | 你能得到什么 |
|--------|----------|--------------|
| 学生 | 对话 / 历史 / 我的 | 讲练与心情分流、学习计划、引用校本资料出题做题；心情内容默认不给老师 |
| 教师 | 出题台 / 班级学情 / 助手 | 快组卷（含文件与校本资料）、看授权学情；碰不到学生心理原文 |
| 管理员 | 管理后台（可收起侧栏） | 管账号与班级、**校本资料**、按班配同意、学情热点与审计 |

下面按「**功能是什么 → 为什么要有 → 对用户意味着什么**」展开。

---

## 4. 学生端功能

### 4.1 智能对话（练习 / 出题 / 心情 / 自动）

**功能是什么**  
一个主对话入口，可切换模式或让系统自动判断：巩固练习、请 AI 出题、聊聊学业心情；也可附上作业截图、讲义文件，或**引用学校发布的校本资料**一起问 / 即时出题做题。

**为什么要有**  
学生真实场景里「不会做」和「很焦虑」经常缠在一起。若系统只会一味刷题，会加重压力；若只能闲聊，又解决不了学业。需要**同一入口、不同路径**，并在高压时主动停加压。

**对用户意味着什么**  
- 想提分时：有阶梯练习与讲解，而不是无差别题海。  
- 想倾诉时：有「仅你可见」的心情对话，降低「说了会被老师知道」的顾虑。  
- 附文件时：对着真实作业/材料提问，减少复述题干的成本。

### 4.2 与 AI 共创学习计划

**功能是什么**  
在对话里一起定目标、天数、每日步骤和聚焦模块；确认后出现在「我的」，可再改。

**为什么要有**  
很多学生不是不知道该学，而是缺一份**自己认、也扛得住**的节奏。纯人工计划难坚持，纯系统推送又像被安排。共创兼顾「有结构」和「有参与感」。

**对用户意味着什么**  
- 学生：从「我该学什么」变成「这周我认下的几步」，降低空转焦虑。  
- 后续练习/出题可对齐计划焦点（学习侧），而不会把心情内容写进计划表。

### 4.3 历史：对话治理 + 多阶段成长总结 +「AI 记得你」

**功能是什么**  
- **对话**：搜索、筛选、置顶、重命名、归档、删除、打开续聊。  
- **成长总结**：按周/阶段列表查看学习侧与支持侧摘要，可归档、对比相邻阶段。  
- **AI 记得你**：展示并纠正长期学习印象与支持印象（后者仅学生可见）。

**为什么要有**  
没有可管历史，AI「懂你」会变成黑箱；只有「本周一张卡」也无法看见成长是阶段性的。学生需要**能整理、能回顾、能纠错**的记忆，而不是一堆聊过就丢的气泡。

**对用户意味着什么**  
- 学生：像整理自己的学习日记——重要会话留着，过期的归档，看清哪几周在进步。  
- 纠错画像：减少「AI 记错了我」带来的不信任。  
- 老师：仍看不到心情历史与支持印象原文。

### 4.4 「我的」：计划入口与画像纠正

**功能是什么**  
查看当前学习计划、纠正学习/支持印象；同意策略以可读说明展示当前生效规则（个性化、历史留存、学情共享等）。

**为什么要有**  
计划与画像需要一个稳定落点；同意若完全散落在学生端随意勾选，学校难统一合规口径——故由校方主导配置（可按班），并保留「学生知情、可与学校一起调整」的空间（调整在管理端完成，学生端先保证知情）。

**对用户意味着什么**  
- 学生：知道「系统记得什么、计划是什么、谁可能看到学情」，并能纠正画像。  
- 学校：同意策略可统一治理，必要时按班或按人调整，而不是各自为政。

## 5. 教师端功能

### 5.1 出题台（知识点 / 文件 / 混合）

**功能是什么**  
按学科与知识点组卷，或上传讲义、试卷按材料仿写；也可**引用管理员发布的校本资料**。生成结果以**题包**归档，可查看修改历史；可用「添加到对话」交给助手继续完善。

**为什么要有**  
教师最耗时的是「对着课标和手头材料变出够用的题」，且改题过程需要可回溯；校本库保证全校材料口径一致。

**对用户意味着什么**  
- 教师：组卷可管理、可版本对比/恢复；直接用校本讲义/试卷出题。  
- 学生（间接）：练到的题更贴课堂进度与本校材料。  
- 边界：不读学生心情画像；重要考试用途仍建议人工审题。

### 5.2 班级学情（授权范围内）

**功能是什么**  
查看已授权学生的正确率、薄弱点等学习指标，以及班级提问模块热点（哪些知识点被问得最多）。

**为什么要有**  
教师需要「班里卡在哪」，但不需要、也不应看到「谁昨晚哭过」。聚合学习侧信号，才能在教研与补差上做决策。

**对用户意味着什么**  
- 教师：备课与分层辅导有据可依。  
- 学生：学情共享需同意；心情与支持内容仍隔离。  
- 学校：学情使用落在可解释的授权边界内。

### 5.3 教学助手对话

**功能是什么**  
教师侧对话（无「心情」入口）：可附本地文件或引用校本资料；对题包气泡「存入出题台」——若已关联题包则追加**新版本**，否则新建题包。

**为什么要有**  
自然语言适合改题与打磨，但结果必须落到可管理、可追溯的题包。

**对用户意味着什么**  
- 教师：出题台「添加到对话」→ 聊改 →「存入出题台」写版本；也可边聊边引用校本。  
- 学生与合规：心理支持通道不会被教师账号占用或旁路偷看。

## 6. 管理端功能

### 6.0 资料管理（校本共用库）

**功能是什么**  
管理员上传/编辑校本材料，设置可见范围（师生 / 仅教师 / 仅学生）与发布状态。教师可引用出题；学生可引用让 AI 即时出题并做题。

**为什么要有**  
个人上传零散、口径不一；校级资料库把「权威材料」与「个人草稿」分开。

**对用户意味着什么**  
- 学校：统一教材与试卷入口，可按角色控制可见性。  
- 教师/学生：只看见已发布且对自己开放的资料，一键引用。

### 6.1 用户与组织班级

**功能是什么**  
维护管理员 / 老师 / 学生账号、启停与角色；维护学校与班级关系。

**为什么要有**  
没有清晰身份与班级边界，「谁能看谁的学情」无法落地。

**对用户意味着什么**  
- 学校：账号生命周期可控（含停用不可登录）。  
- 教师/学生：权限跟组织关系走，转班离班可收回学情可见范围。

### 6.2 同意设置（校级 → 班级模板 → 学生覆盖）

**功能是什么**  
配置画像个性化、历史留存、学情是否共享给老师等开关；按班级筛选与分组，支持班级模板「应用到本班」。

**为什么要有**  
同意是产品信任的底座。需要校方统一默认，又要能「一班一策」、个别覆盖；学生侧重在知情，重大调整与学校一起完成，而不是黑箱。

**对用户意味着什么**  
- 学校：有统一默认，又能按班批量或按人微调。  
- 教师：只有被允许共享的学生学习侧可看。  
- 学生：清楚「谁可能看到我的学情」；心情与支持内容仍不在可放开给老师的范围内。

### 6.3 学情分析（模块热点 + 学生提问分布）

**功能是什么**  
汇总「整体哪些知识点/模块被问得最多、覆盖多少人」，以及「每个学生常问什么」。

**为什么要有**  
仅有个别人错题，看不清系统性薄弱。提问频率是**真实困惑的信号**，对教研选题与补差班设计很有价值。

**对用户意味着什么**  
- 学校/教研：发现共性卡点，调教学节奏。  
- 教师（班级视图）：补课更对准「班问最多的模块」。  
- 学生：分析只用学习侧提问，不含心情原文。

### 6.4 审计日志

**功能是什么**  
记录门禁拒绝、危机短路、账号启停等关键动作（脱敏）。

**为什么要有**  
教育场景一旦涉及情绪与未成年人，出事要能回答「谁在何时做了什么」。

**对用户意味着什么**  
- 学校：合规举证与内部追责有依据。  
- 学生/家长（间接）：系统承诺可被核查，而不只是口号。

## 7. 贯穿各端的关键能力

### 7.1 教学与支持「分流」

**为什么要有**  
混在一个「全能聊天」里，最容易在学生示弱时继续催刷题，也最容易把情绪细节泄漏到教学视图。

**对用户意味着什么**  
练归练、聊归聊；高压时系统会停加压，而不是「再来十道」。

### 7.2 文件能力（对话附件 + 文件出题）

**为什么要有**  
真实学习发生在讲义、试卷和错题本上，而不是空白对话框里。

**对用户意味着什么**  
学生可对着材料提问；教师可对着材料组卷；心情会话里的附件仍仅本人可见。

### 7.3 「专属感」来自记忆，而不是常驻进程

**功能是什么**  
每位学生有可更新的学习/支持画像、阶段总结与可纠正印象。

**为什么要有**  
学生要的是「你还记得我上次卡在二次函数」，而不是每次从零自我介绍。

**对用户意味着什么**  
连续陪伴感；同时支持侧记忆默认不出学生域，避免「被系统卖给老师」。

## 8. 使用中的安全与信任边界（用户能感知到的）

这些不是「给研发看的条款」，而是功能承诺的一部分：

| 承诺 | 用户侧感受 |
|------|------------|
| 学业情绪支持，不是看病开药 | 文案与能力边界清晰，危机时给求助指引而非假装治疗 |
| 老师默认看不到心情原文与支持摘要 | 学生敢说；老师也不被塞无用的隐私 |
| 学情共享需同意/校策，并受班级关系约束 | 「看见」有理由、有范围 |
| 高风险时停止加压练习与加压计划 | 脆弱时刻不被题海追着打 |
| 关键操作可审计 | 学校能查、能改、能交代 |

更细的技术与表结构见系统设计、LangGraph 与数据库文档。

## 9. 当前进展与下一步（产品视角）

**已经能演示的**  
三角色前端（登录分流、学生对话/历史/计划/文件、教师出题台与学情、管理侧栏与按班同意、学情分析）；后端主图骨架（路由、门禁、风险、计划与提问分析等占位）。

**对用户而言还缺什么**  
真实大模型效果、文件真正解析、历史/学情与后台配置的正式联网与持久化——近程会优先补齐「用起来真像产品」的联调，再强化多轮练习与人在回路审题。

开放复用上，分流思路、双域可见性、学情聚合与文件增强教学，可迁到校本助手、学科练习助手等场景。
