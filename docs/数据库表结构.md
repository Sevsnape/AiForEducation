## 1. ER 关系（逻辑）

```text
organizations ──< class_groups ──< memberships >── users
users ──< role_bindings
users ──< consents
users ──< threads ──< messages
              └────< session_summaries
users ── student_profiles
users ──< profile_corrections
users ──< artifacts
users ──< learning_events
users ──< weekly_summaries
* ──< audit_logs
```

## 2. 表说明

### 2.1 身份与租户

| 表 | 用途 |
|----|------|
| `users` | 账号主体 |
| `organizations` | 学校/机构（可空，个人版无组织） |
| `class_groups` | 班级/教学班 |
| `role_bindings` | 全局或组织内角色：student/teacher/admin |
| `memberships` | 班级成员关系（师生绑定，老师看学情的关系条件） |
| `consents` | 同意开关（可带 org 作用域） |

**Consent 字段**

| 列 | 含义 |
|----|------|
| `learning_personalize` | 是否用画像个性化 |
| `history_retain` | 是否留存会话 |
| `share_learning_with_teacher` | 是否共享学情给老师 |

### 2.2 会话与历史

| 表 | 用途 | 可见性 |
|----|------|--------|
| `threads` | 会话线程 | 仅 owner |
| `messages` | 原文消息（含 counsel） | 仅 owner；老师 API 不查 |
| `session_summaries` | 会话摘要 | 学生；support_tags 不对老师 |

### 2.3 学生画像

| 表 | 用途 |
|----|------|
| `student_profiles` | 长期画像：`learning_json` + `support_json` |
| `profile_corrections` | 学生纠正记录 |

**硬规则**：任何老师查询路径不得 SELECT `support_json` / counsel 类 `messages`。

`learning_json` / `support_json` 字段形态见系统设计草案第 5 章。

### 2.4 学业产物

| 表 | 用途 |
|----|------|
| `artifacts` | 题包/练习包等结构化产物 |
| `learning_events` | 答题、完成练习等事件 |
| `weekly_summaries` | 成长周报（support_text 仅学生） |

### 2.5 审计

| 表 | 用途 |
|----|------|
| `audit_logs` | 鉴权、危机短路、导出、管理员访问等 |

## 3. 与 LangGraph 持久化的分工

| 存储 | 内容 |
|------|------|
| **业务 SQL（本文件）** | 用户、同意、消息原文、Profile、Artifact、审计 |
| **LangGraph Checkpointer** | 同一 `thread_id` 的图执行中间态（续聊 / interrupt） |
| 不把 `support_json` 写入老师可读视图或检查点明文日志 |

Checkpointer 推荐生产用 Postgres（`langgraph-checkpoint-postgres`）；开发可用 Memory / SQLite。
