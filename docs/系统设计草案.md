> 技术方向：LangGraph 多 Agent

## 1. 产品定位

### 1.1 一句话

做 **学生主视角的支持 AI**：帮助巩固学习、协助老师出题，并提供学业相关的情绪支持；在混合（学校 + 个人）场景下，**老师看见“学得怎样”，AI 才真正“懂这个学生”**——“懂”的支持侧信息默认只对学生本人开放。

### 1.2 场景选择

| 维度 | 结论 |
|------|------|
| 部署场景 | **混合**：有老师即带学校协作能力，但产品灵魂是学生支持 |
| 老师角色 | 出题、布置/审阅练习、查看授权范围内学情 |
| 心理/支持模块 | **不对老师展示**（原文与摘要均隔离） |
| 会话留存 | **需要**，并提供学生侧历史与总结 |
| 专属感实现 | 每学生一份 Memory Profile + 总结 Agent，而非一人一常驻进程 |

### 1.3 能力范围

| 能力 | 说明 |
|------|------|
| 出题 | 按知识点、难度、题型生成；支持变式、答案与解析；服务老师组卷与学生练习 |
| 巩固学习 | 测 → 诊 → 练 → 再测闭环；错题归因、阶梯练习 |
| 学业心理支持 | 倾听、情绪命名、压力疏导、学习动机；**非临床诊疗** |
| 学生历史与画像 | 会话留存、阶段总结、「AI 记得你」可读可纠错 |

### 1.4 明确不做（MVP）

- 临床心理诊断、治疗建议、开药
- 老师查看心理原文或支持侧摘要
- 家长角色（二期再议）
- 危机自动通知任课老师（若未来有校方安全协议，走独立合规流程，不进入 MVP）

## 2. Agent 总体架构

### 2.1 推荐形态：Supervisor + 专家子图

不采用单一超级 Agent，而采用意图路由 + 多角色子图 + 共享记忆。

```text
用户输入
  → 安全与合规门禁（guard）
  → 意图路由 Supervisor
       ├─ 出题 Agent
       ├─ 巩固练习 Agent
       ├─ 学习诊断 Agent
       └─ 心理辅导 Agent → 危机识别与转介
  → 质检 / 统一回复组装
  → 写回会话与（异步）画像更新
```

### 2.2 角色职责

| 角色 | 职责 | 不该做的事 |
|------|------|------------|
| Supervisor | 识别身份（老师/学生）、意图、是否加载支持侧上下文、是否转交 | 不亲自长篇出题或做深度心理干预 |
| 出题 Agent | 按知识点/难度/题型生成；结构化题目与解析 | 不做心理安慰；不把情绪细节写进题面 |
| 巩固练习 Agent | 错题归因、阶梯练习、讲解、小测 | 不替代正规心理咨询 |
| 学习诊断 Agent | 薄弱点、掌握度、推荐路径 | 不编造成绩或越权改分 |
| 心理辅导 Agent | 倾听、情绪支持、学业压力疏导 | 不做诊断、不开药；危机时必须转介话术 |
| 总结 Agent（异步） | 会话摘要 → 滚动更新 Student Profile | 不把心理原文写入老师可见视图 |

### 2.3 出题可验收输入输出（约定）

- **输入**：学科、年级、知识点、题型、难度、数量、是否含解析  
- **输出**：结构化数据（题干 / 选项 / 答案 / 解析 / 考点标签）  
- **质检节点**：答案自洽、难度标签、敏感内容

### 2.4 风险与练习链路隔离

当 `risk_level = high` 时：

- Supervisor **切断自动推题 / 加压练习**
- 仅走安全回复与求助资源指引
- 相关处理写入审计日志

## 3. 详细情况如何记录

### 3.1 四层档案

| 层 | 记什么 | 用途 | 敏感度 |
|----|--------|------|--------|
| 会话轨迹 | 每轮消息、走了哪个 Agent、工具调用、耗时/模型 | 复盘、调试、质检、学生历史 | 中 |
| 学情档案 | 知识点掌握度、错题、练习节奏、难度轨迹 | 巩固学习、出题个性化、老师授权查看 | 中 |
| 辅导情境 | 情绪标签、压力主题、风险等级、是否转介（**尽量少记原文进画像**） | 支持连续性与安全 | 高 |
| 权责审计 | 谁在何时访问/导出/修改了什么 | 合规、纠纷举证 | 高 |

### 3.2 概念实体

```text
User
  └─ RoleBinding（student / teacher / admin）
  └─ Consent（学情个性化、历史留存、学情共享给老师等）
Session / Thread
  └─ Turn / Message
  └─ Session Summary
  └─ Artifact（试卷草稿、练习集、解析、导出版本）
LearningProfile（学情，见第 5 章 learning 域）
CounselContext / Support Profile（支持侧，见第 5 章 support 域）
AuditLog
```

### 3.3 记录原则

1. **教学数据可详，心理数据摘要优先**  
   - 学情：题、对错、知识点、时间可详记  
   - 心理：优先记情绪标签 / 主题 / 风险 / 是否转介 / `safe_summary`  
   - 原文保留在学生私有历史中，短中期可删，不对老师全量开放

2. **一次交互可还原**  
   每条 Turn 建议包含：`who` · `intent` · `agent` · `inputs_ref` · `outputs_ref` · `risk` · `consent_scope` · `timestamp`

3. **产物与对话分离**  
   试卷、练习集为可版本化 `Artifact`；对话为 `Message`。老师审题看产物，不必翻完整私聊。

4. **状态机优于无限日记**  
   - 辅导：`stable → distressed → crisis`  
   - 学习：`diagnose → practice → retest`  
   详细情况 = 结构化状态 + 必要摘要

### 3.4 「专属 Agent 感」的实现方式

- **不是**每个学生一个常驻进程 Agent  
- **而是**每个学生一份 `Student Memory Profile`，请求时由 Supervisor 注入专家子图  
- 学生可在「AI 记得你」中阅读与纠正画像，形成可信的专属感

分层记忆：

1. `Message`：原始消息（历史页）  
2. `Session Summary`：一会话结束短摘要  
3. `Student Profile`：定期/阈值触发的长期画像  
4. `Retrieval`：当前问题按需检索相关历史片段

## 4. 用户权责体系

### 4.1 角色权利与责任

| 角色 | 权利 | 责任 |
|------|------|------|
| 学生 | 练习、查看自己学情与完整历史、使用支持模块、纠正画像、删除/导出部分个人数据 | 辅导内容为支持非医疗；不恶意伪造危机骚扰系统 |
| 老师 | 出题、组卷、查看**授权范围内**学情与练习结果、审题发布 | 不把心理内容当考核材料；不越权查看辅导详情 |
| 管理员/学校 | 配置学科、审计、合规策略、账号生命周期 | 最小必要访问；保管密钥与留存策略 |
| 家长 | **二期** | — |

### 4.2 权限模型

采用「角色 × 资源 × 动作 × 条件」：

```text
teacher 可 read  LearningProfile
  当 relationship=授课班级 且 purpose=教学 且 consent.share_learning_with_teacher=true

teacher 不可 read  CounselTranscript / support Profile（MVP 全拒绝）

student 可 delete  自己的 Messages（在留存与政策允许范围内）

admin 可 read  AuditLog；其访问本身也记审计
```

关键条件字段：关系、目的、同意范围、风险等级（危机突破仅留作未来校方面政策，不进 MVP 老师可见）。

### 4.3 同意（Consent）一等公民

| 开关 | 默认倾向 | 说明 |
|------|----------|------|
| 学情用于个性化练习 | 可开 | 关闭则不做长期学习画像个性化 |
| 会话历史留存 | 需明确 | 关闭则弱化跨会话记忆 |
| 学情共享给任课老师 | 需明确或校方统一政策 | 关闭则老师不可看该生学情详情 |

无同意时：仍可做通用答疑/出题，但 **不写长期画像、不共享、不跨会话强调支持侧记忆**。

### 4.4 心理路径权责红线

- 定位为 **学业情绪支持**，不是诊疗或危机干预替代品  
- 高风险：停止刷题链路，提供求助资源  
- **老师默认看不到心理原文与支持摘要**  
- 危机处理进 `AuditLog`，保证流程可追溯  

### 4.5 数据可见性与留存（默认策略）

| 数据类型 | 默认留存 | 学生 | 老师 | 管理员 |
|----------|----------|------|------|--------|
| 练习对错/知识点 | 1–2 学年 | 读写自己的 | 读授权班级 | 审计用 |
| 试卷产物 | 按课程周期 | 读已发布 | 读写自己创建的 | 审计 |
| 辅导/私聊原文 | 30–90 天可删（可配置） | 读/删自己的 | **不可见** | 极少数合规访问 |
| 支持侧摘要/风险标记 | 可稍长 | 可见 | **不可见（MVP）** | 审计 |
| 审计日志 | 更长（合规期） | 通常不可见 | 不可见 | 可读 |

## 5. Student Profile 字段草案

Profile 分两域：`learning`（学习侧）、`support`（支持侧）。老师 API **永远不返回 `support`**。

### 5.1 元信息

| 字段 | 类型 | 说明 | 进 State | 进 DB |
|------|------|------|:--------:|:-----:|
| `student_id` | string | 学生 ID | ✅ | ✅ |
| `profile_version` | int | 每次滚动更新 +1 | ✅ | ✅ |
| `updated_at` | datetime | 最近画像更新时间 | ✅ | ✅ |
| `source` | enum | `auto_summary` / `student_correction` / `hybrid` | | ✅ |
| `consent.learning_personalize` | bool | 是否用画像个性化练习 | ✅ | ✅ |
| `consent.history_retain` | bool | 是否留存会话历史 | ✅ | ✅ |
| `consent.share_learning_with_teacher` | bool | 学情是否共享给老师 | ✅ | ✅ |

### 5.2 学习侧 `learning`

| 字段 | 类型 | 说明 | 进 State | 进 DB |
|------|------|------|:--------:|:-----:|
| `subjects_focus` | string[] | 当前主攻学科 | ✅ 摘要 | ✅ |
| `weak_knowledge` | `{tag, level, evidence}[]` | 薄弱知识点（最多约 8 条） | ✅ | ✅ |
| `strong_knowledge` | string[] | 相对扎实点（最多约 5） | 可选 | ✅ |
| `preferred_question_types` | string[] | 偏好/适应题型 | ✅ | ✅ |
| `difficulty_sweet_spot` | 1–5 | 当前合适难度 | ✅ | ✅ |
| `practice_rhythm` | enum | `short_frequent` / `long_deep` | ✅ | ✅ |
| `common_error_patterns` | string[] | 错因模式 | ✅ | ✅ |
| `near_term_goal` | string | 近期学习目标（一句话） | ✅ | ✅ |
| `last_practice_snapshot` | object | 最近练习摘要 | ✅ | ✅ |
| `teaching_notes_for_ai` | string | AI 教学策略备忘 | ✅ | ✅ |

**老师可见（需同意）**：`weak_knowledge`、`last_practice_snapshot`、可选 `near_term_goal`。不含聊天原文与支持侧。

### 5.3 支持侧 `support`（仅学生域）

| 字段 | 类型 | 说明 | 进 State | 进 DB |
|------|------|------|:--------:|:-----:|
| `current_mood_trend` | enum | `stable` / `stressed` / `low` / `volatile` | ✅ | ✅ |
| `stress_themes` | string[] | 压力主题标签 | ✅ | ✅ |
| `triggers` | string[] | 易触发点 | ✅ | ✅ |
| `what_helps` | string[] | 有效支持方式 | ✅ | ✅ |
| `what_to_avoid` | string[] | AI 应避免的做法 | ✅ | ✅ |
| `support_preference` | enum | `warm` / `direct` / `structured` | ✅ | ✅ |
| `risk_level` | enum | `none` / `watch` / `high` | ✅ | ✅ |
| `last_risk_at` | datetime\|null | 最近一次非 none | 辅导节点需要 | ✅ |
| `safe_summary` | string | 给 AI 的安全摘要（非原文） | ✅ | ✅ |
| `referral_flag` | bool | 是否曾触发转介话术 | ✅ | ✅ |

**硬规则**

- `support.*` 不对老师、家长开放（MVP）  
- 原始聊天不进 Profile，只进 History  
- `risk_level=high` 时切断自动推题  

### 5.4 Profile 更新策略

| 触发 | 动作 |
|------|------|
| 会话正常结束 | 生成 Session Summary → 异步合并进 Profile |
| 累计 N 轮或每周 | 强制滚动重摘要，防止画像漂移 |
| 学生纠正「AI 记得你」 | 覆盖对应字段，`source=student_correction` |
| 学生删除某段历史 | 标记 `needs_resummary`，后台重算 |

合并方式：LLM 输出 **结构化 patch**（改 JSON 字段），避免整篇散文覆盖。

## 6. 历史模块信息架构（学生端）

### 6.1 页面结构

```text
历史
├─ 顶部：搜索 + 筛选（类型 / 时间 / 学科）
├─ Tab A：对话
├─ Tab B：成长总结
└─ Tab C：AI 记得你
```

老师端无对等「对话 / AI 记得你」；另设「班级学情 / 练习报告」。

### 6.2 Tab A · 对话

**列表项**

| 字段 | 说明 |
|------|------|
| `thread_id` | 会话 ID |
| `title` | 自动标题（可改） |
| `primary_intent` | `practice` / `question_help` / `counsel` / `mixed` |
| `started_at` / `last_active_at` | 时间 |
| `preview` | 预览；counsel 可用泛化文案如「情绪支持会话」 |
| `has_artifact` | 是否产生练习/试卷 |

**详情**：完整消息流（仅学生）· 本会话 Summary · 关联 Artifact · 操作：继续聊 / 删除 / 基于此会话更新画像。  
`intent=counsel` 会话展示「仅你可见」标识。

### 6.3 Tab B · 成长总结

| 卡片 | 内容 | 可见性 |
|------|------|--------|
| 本周学习 | 练习次数、正确率、薄弱点变化 | 学生；授权后部分给老师 |
| 本周支持 | 压力主题、情绪趋势、是否放缓节奏 | **仅学生** |
| 下一步建议 | 学习计划；风险偏高则偏恢复 | 学生；若给老师仅脱敏学业建议 |

频率：每周自动 + 学生手动生成。

### 6.4 Tab C · AI 记得你

1. **学习印象**：由 `learning.*` 生成自然语言 + 纠正  
2. **支持印象**：由 `support.*` 生成自然语言 + 纠正，并标明「老师看不到」  

纠正尽量对应结构化字段（标签多选 + 短文本）。

## 7. LangGraph State 与持久化划分

### 7.1 只进 DB、默认不进 State

- `Message` 全文  
- `AuditLog`  
- `Artifact` 大正文（按 ID 按需加载）  
- 旧版本 Profile  
- 师生关系、同意书原文  

### 7.2 State 当回合切片（建议）

```text
state = {
  user_id, role,
  consent_flags,
  intent, risk_level,

  learning_snapshot: {
    weak_knowledge,
    difficulty_sweet_spot,
    practice_rhythm,
    common_error_patterns,
    near_term_goal,
    last_practice_snapshot,
    preferred_question_types,
  },

  support_snapshot: {            # 仅学生；老师请求时必须为空
    current_mood_trend,
    stress_themes,
    what_helps,
    what_to_avoid,
    support_preference,
    risk_level,
    safe_summary,
    referral_flag,
  },

  retrieved_history: [...],      # 0–5 段短摘录
  session_summary_so_far: "...",
  current_artifact_id: "...",
  teacher_view: false
}
```

### 7.3 注入规则

| 角色 / 意图 | learning_snapshot | support_snapshot | retrieved_history |
|-------------|-------------------|------------------|-------------------|
| 学生 · 练习/出题求助 | ✅ | 可选（只调节题量/节奏，不入题面） | 偏学业片段 |
| 学生 · 辅导 | 弱相关可选 | ✅ | 偏支持片段 + safe_summary |
| 老师 · 出题/看报告 | 班级聚合学情 | ❌ 强制空 | ❌ 学生私聊 |

### 7.4 逻辑表

```text
users
role_bindings
consents
threads
messages
session_summaries
student_profiles          # JSON: learning + support + version
profile_corrections
artifacts
learning_events
audit_logs
```

### 7.5 Agent 读写对照

| Agent | 主要读 | 主要写 |
|-------|--------|--------|
| Supervisor | consent, risk, role | intent；是否加载 support |
| 出题 / 练习 | learning_snapshot | learning_events, artifacts；异步更新 learning |
| 辅导 | support_snapshot + 少量 history | messages；更新 support 摘要与 risk |
| 总结 Agent | 近期 messages + 旧 profile | session_summaries, student_profiles |
| 老师出题 | 课标/知识点 + 可选班级学业聚合 | artifacts；不读 support / 私聊 |

弱关联允许：支持侧显示压力大 → 练习侧降低题量；**若结果暴露给老师，只能是学业建议，不能带情绪原因**。

## 8. 组织与关系模型（混合场景）

个人可用，学校可挂组织，避免一上来做成重型教务系统。

```text
Organization（学校/机构，可空 = 个人版）
  └─ ClassGroup（班级/教学班）
       └─ Membership
            ├─ teacher 绑定
            └─ student 绑定
User
  └─ RoleBinding（全局或组织内角色）
  └─ Consent（可带 org_id 作用域）
```

| 规则 | 说明 |
|------|------|
| 无组织学生 | 完整学生 AI；无老师共享对象 |
| 有组织学生 | 学情共享仍受 `consent.share_learning_with_teacher` 约束 |
| 老师看学情 | 仅 `Membership` 覆盖的学生 + 同意 + 仅 learning |
| 换班/离职 | 撤销关系后老师立即失去该生学情读权限；历史审计保留 |

MVP 可先实现：User + RoleBinding + 可选 `class_id` 字符串关联；Organization 表可二期硬化。

## 9. 对外能力轮廓（逻辑 API）

实现前只定资源，不绑框架。

### 9.1 对话与 Agent

| 能力 | 说明 |
|------|------|
| `POST /agent/invoke` | 主对话入口（学生/老师） |
| `POST /agent/resume` | 练习作答后续跑 |
| `GET /threads` | 学生会话列表 |
| `GET /threads/{id}` | 会话详情（本人） |
| `DELETE /threads/{id}` | 删除会话并触发重摘要标记 |

### 9.2 画像与历史

| 能力 | 说明 |
|------|------|
| `GET /me/profile` | 学习侧 + 支持侧（仅本人） |
| `PATCH /me/profile` | 纠正「AI 记得你」 |
| `POST /me/profile/resummary` | 手动重摘要 |
| `GET /me/weekly-summary` | 成长总结 |

### 9.3 老师侧

| 能力 | 说明 |
|------|------|
| `POST /teacher/question-gen` | 出题（可走同一 graph，`teacher_view=true`） |

| `GET /teacher/students/{id}/learning` | 单生 learning（鉴权+同意）；**无 support 字段** |

### 9.4 合规

| 能力 | 说明 |
|------|------|
| `GET/PUT /me/consents` | 同意开关 |

| `GET /admin/audit` | 审计查询 |

所有返回学生相关 JSON 的接口，序列化层必须经过「按查看者过滤」。

## 10. 交互与文案原则

### 10.1 学生主界面信息架构（MVP）

```text
首页对话（默认）
  ├─ 快捷模式：练习 / 请你出题 / 聊聊心情
  ├─ 历史
  └─ 我的（同意设置、AI 记得你、导出/删除说明）
```

老师另入口：出题台 + 班级学情（无「心情历史」）。

### 10.2 必显说明（产品文案要点）

- 支持模块为 **学业情绪支持**，不能替代心理咨询或医疗机构  
- 心情相关对话 **默认仅自己可见**  
- 高风险场景将提供求助资源，并可能限制继续刷题  
- 出题结果可能存在错误，重要考试用途需人工审阅  

### 10.3 UI 提示位（供 Agent `ui_hints`）

| hint | 含义 |
|------|------|
| `show_private_badge` | 展示「仅你可见」 |
| `disable_more_practice` | 高风险或压力大时禁用「再来一题」 |
| `suggest_counsel_first` | 混合意图时建议先稳情绪 |
| `needs_teacher_review` | 题目待老师审（二期） |

## 11. 安全、内容与合规补充

### 11.1 输入 / 输出安全分层

| 层 | 作用 |
|----|------|
| 输入 risk_screen | 自伤他伤、严重危机等 → safety 短路 |
| 专家 system 约束 | counsel 禁止诊断/开药；出题禁止侮辱性内容 |
| 输出 post_risk / review | 二次拦截不当回复与题面 |
| 审计 | safety 触发、越权尝试、导出与管理员查看 |

### 11.2 出题内容政策（摘要）

- 不生成歧视、色情、暴力或人身攻击内容  
- 不生成「可直接用于作弊且无学习价值」的整卷答案钥匙给未授权场景（学生求讲解可给解析，老师组卷另议）  
- 学科事实以课标/知识点标签约束，减少超纲胡编（RAG/题库二期加强）  

### 11.3 未成年人与学校场景

- 默认按未成年人保护更严档设计文案与留存  
- 学校部署时 Consent 可由机构策略模板初始化，但仍应让学生可见「谁能看到我的学情」  
- 运营与管理员访问支持侧原文：MVP **原则上不允许**；若合规需要，二期走独立审批与审计  

### 11.4 密钥与模型调用

- API Key 仅存服务端  
- 日志脱敏：避免完整 support 原文与可直出 PII  
- 按环境隔离 Checkpointer / DB

## 12. 非功能需求（初值，可调）

| 项 | MVP 目标 |
|----|----------|
| 首 token / 首包感知 | 对话流式优先；路由+安全节点合计尽量短 |
| 可用性 | 单专家失败可降级提示，不拖垮主 API |
| 可追溯 | 每回合 `trace_id`；关键决策有 `route_reason` |
| 隐私 | privacy 自动化用例：老师响应无 support |
| 数据删除 | 学生删会话后，画像重摘要可异步完成 |
| 多租户 | 预留 `org_id`；MVP 可单租户部署 |

## 13. 观测与成功指标

### 13.1 产品指标（方向）

| 指标 | 说明 |
|------|------|
| 练习完成率 / 再测提升 | 巩固是否有效 |
| 出题采纳率（老师） | 生成题是否可用（可辅以人工评分） |
| 支持会话后「愿意继续学习」比例 | 弱关联，不把情绪当考核 |
| 画像纠正率 | 过高说明自动摘要漂移 |
| safety 触发准确率（抽样） | 风险模块质量 |

### 13.2 工程指标

- 路由准确率（评测集）  
- review 通过率 / 重试率  
- 老师路径 support 泄漏次数（目标为 0）

## 14. MVP 范围、二期与实现顺序

### 14.1 MVP 做

- LangGraph：guard → route → 出题/练习/辅导（可含简易诊断）→ assemble  
- 学生历史三 Tab  
- Profile 两域 + 学生纠正  
- 会话留存 + Session Summary + 滚动画像  
- 老师完全隔离 support  
- 出题结构化输出 + 基础质检  
- 同意开关 + 基础审计 + 安全短路  

### 14.2 二期再议

- 家长角色  
- 危机通知校方 / 人工值守协议  
- 老师侧「建议减负」等脱敏信号  
- 人在回路审题发布流  
- 间隔复习与更完整知识点图谱 / RAG  
- 组织与班级模型硬化、导出合规包  

### 14.3 建议实现顺序

1. 数据模型 / 表结构与 Pydantic Schema  
2. LangGraph State + 主图空壳（见《LangGraph框架思路》Phase 1–2）  
3. 出题专家 + review  
4. 练习多轮（Checkpointer）  
5. 辅导子图 + 风险门禁  
6. 总结 Agent（历史 → Profile）  
7. 学生历史与「AI 记得你」API/页面  
8. 老师出题台与学情只读 API  

更细的图节点与目录规划见 [LangGraph框架思路.md](./LangGraph框架思路.md)。
