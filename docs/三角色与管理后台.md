# 三角色与管理后台说明

> 与前端 `apps/web`、SQL `role_bindings` 对齐  
> 学情分析详见 [学情分析与问题模块.md](./学情分析与问题模块.md)

## 结论

**需要独立的管理后台。**  
学生端做支持与学习，老师端做出题与学情，**管理员负责用户生命周期、学情聚合与合规审计**，三者入口分离，避免把账号管理塞进学生对话产品里。

## 三角色职责

| 角色 | 产品入口 | 能做什么 | 明确不能做什么 |
|------|----------|----------|----------------|
| **学生** | `/student/*` | 对话（含**学习计划共创**）、练习、出题求助、心情支持、历史与画像纠正；**引用校本资料**即时出题做题 | 管理他人账号；看别人私聊；**暂不自助改同意开关** |
| **老师** | `/teacher/*` | 出题台（题包库+版本、引用校本）、授权班级学情、教学助手（题包存取） | 看学生 support / 心情原文；进管理后台 |
| **管理员** | `/admin/*` | 用户 CRUD/启停、角色绑定、组织班级、**资料管理**、同意策略、学情分析、审计 | 浏览学生心理原文（审计仅动作与脱敏字段） |

一人可多角色绑定（如既是老师又是校内管理员），由 `role_bindings` 表达；前端 Mock 暂按「登录后按账号角色进对应端」演示。

## 管理后台模块

1. **用户管理**：创建账号、分配 student/teacher/admin、启用/停用  
2. **组织班级**：学校租户与班级成员关系（老师看学情的关系边界）  
3. **资料管理**：校本共用材料上传/发布/可见范围（教师出题、学生练习可引用）  
4. **同意设置**：校级默认 + 学生覆盖（学生端暂不开放自助修改，见 [同意策略管理员配置.md](./同意策略管理员配置.md)）  
5. **学情分析**：学业提问模块热点 + 每名学生常问模块（表 `question_asks`）  
6. **审计日志**：门禁拒绝、危机短路、账号启停等  

**导航形态**：顶栏品牌与账号 + **可收起/展开的左侧侧边栏**（`/admin/users|orgs|materials|consents|analytics|audit`）。

二期可加：同意策略模板批量导入、导出合规包、模块词表管理。

## 与数据表对应

- `users` + `role_bindings` + `memberships` + `consents` → 用户管理  
- `organizations` + `class_groups` → 组织班级  
- `shared_materials` + `shared_material_refs` → 资料管理（见 [文件对话与文件出题.md](./文件对话与文件出题.md)）  
- `question_asks`（+ 可选关联 `learning_events`）→ 学情分析  
- `audit_logs` → 审计  

## 前端现状

入口为**登录页**（邮箱+密码），校验通过后按账号角色进入对应端；停用账号无法登录。  
管理端路由已切侧栏；学情分析页为 Mock，与后端 `AnalyticsService` demo seed 对齐。

演示账号见 `apps/web/README.md`。
